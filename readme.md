## 同学 B 与同学 C 的耦合接口

同学 B（压缩编码器）和同学 C（解压译码器）通过 **`.huff` 二进制文件格式** 对接。C 不依赖 B 的代码，只依赖 B 输出的文件格式。

### .huff 文件格式（B 的输出 = C 的输入）

```
┌────────┬──────────┬───────────────────────────────────┐
│ 偏移量 │ 大小     │ 字段                              │
├────────┼──────────┼───────────────────────────────────┤
│ 0      │ 4 bytes  │ 魔数：b'HUFF'（C 用于校验）        │
│ 4      │ 1 byte   │ 末尾字节填充位数（0–7）            │
│ 5      │ 2 bytes  │ 密码本条目数 N（uint16, 大端）     │
│ 7      │ 可变     │ N 条密码本记录                     │
│        │          │   - 4B：Unicode 码点 (uint32)     │
│        │          │   - 1B：编码比特长度 L            │
│        │          │   - ceil(L/8)B：编码比特（左对齐） │
│ ...    │ 可变     │ 压缩后的比特流数据                 │
└────────┴──────────┴───────────────────────────────────┘
```

### 密码本条目的比特编码约定

每一条密码本记录中，"编码比特"字段采用 **MSB-first、左对齐** 方式存储：

```
例如字符 'e' 的霍夫曼编码为 "011"（3 bits）：

  code_point = 0x00000065   （4 bytes, uint32 大端）
  bit_len    = 0x03         （1 byte）
  code_bytes = 0b01100000   （1 byte，左对齐，低位补 0）
```

### C 解码时如何消费

1. 读 4 字节魔数，确认是 `HUFF`
2. 读 1 字节 padding，知道数据段末尾多少 bit 无效
3. 读 2 字节 N，知道密码本有多少条记录
4. 循环 N 次解析密码本，重建霍夫曼树
5. 剩余全部字节 = 压缩数据，逐 bit 走树解码

### 约定清单（B 必须保证，C 以此为前提）

| 约定项 | 说明 |
|--------|------|
| 魔数 | 固定为 `b'HUFF'`（4 bytes） |
| 字节序 | 所有多字节整数使用 **大端序（big-endian）** |
| 编码比特存储 | MSB-first，左对齐 |
| 树遍历规则 | `0` = 左子节点，`1` = 右子节点 |
| 填充 | 数据段末尾 padding bit 数存入文件头第 5 字节 |
| 字符编码 | 使用 Unicode 码点（`ord(c)`），支持所有 Unicode 字符 |

## 使用方法

```bash
# 压缩文本文件（同学B）
python main.py compress input.txt -o compressed.huff

# 解压 .huff 文件（同学C的模块）
python main.py decompress compressed.huff -o output.txt

# 完整流程：压缩 → 解压 → 验证报告
python main.py run input.txt
```

## 算法简介

**霍夫曼编码**是一种贪心算法，用于构建最优前缀码：

1. 统计输入文本中各字符的出现频率
2. 为每个字符创建叶子节点，压入最小堆
3. 反复合并频率最小的两个节点，生成内部节点
4. 最终二叉树定义编码：左分支 = `0`，右分支 = `1`
5. 高频字符获得短编码，低频字符获得长编码
6. 前缀无关性（prefix-free）保证解码无歧义，无需分隔符
